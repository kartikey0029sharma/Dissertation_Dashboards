Extract the data

Each button downloads everything collected so far in that table. The survey file has one row per vignette; the interview file has one row per participant; the combined file is the survey with each participant's interview answers repeated across their rows, which is the shape the analysis script expects.

Neither file contains personal data. The study collects no name, no email address and no IP address, so a response can only be identified by its reference, which the participant alone holds.

Upload data collected offline

Use this for responses that did not reach the store: a participant who emailed their own file after a failed send, or a batch typed up from paper. Select one file or many. A single file may hold hundreds of participants; it is split into batches automatically.

1. Start from a template

Two shapes are accepted. The uploader works out which one you have from the header row, so you do not have to say.

Survey only. One row per vignette. Eight rows per participant, all sharing a response_id, with position running 1 to 8.
Survey plus written interview. The same, followed by the interview columns. Repeat each participant's interview answers on every one of their rows, or fill them on the first row only. Either works: the first non-empty value per participant is taken.

Notes

Shape of the data

A participant who finishes the survey contributes eight rows sharing a response_id; the written interview adds one row keyed on the same id. Join on that column to move between vignette level, participant level and interview level.

Re-uploading is safe

Rows are keyed on response_id and position, so uploading the same file twice replaces those rows rather than duplicating them. That makes it safe to fix a typo in a spreadsheet and upload the whole thing again.

If the store is ever unreachable

The Cloudflare dashboard can run SELECT * FROM survey against the D1 database directly and export the result, which is the same data by another route.
